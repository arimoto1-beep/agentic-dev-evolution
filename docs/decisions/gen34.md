## この Run が見た状態

人からの指示は gen33 と似た形でしたが、**一点だけ性質が違いました。**

> この記事には、確認できた事実だけでなく、調査しても最後まで確認できなかった点が
> 含まれています。(中略)記事が断定していないことを断定しないでください。
> 未確認の部分を「もっともらしい答え」で埋めることより、何が確認できていて、
> 何がまだ分からないのかを視聴者が理解できることを優先してください。

記事を読むと、たしかに主張が 3 層に分かれています。

| 層 | 例 |
| --- | --- |
| 確認できた事実 | 諸元表の「ド・ディオン式」/ 下から見た形 / 2008 ライフ・2005 ステップワゴン・2011 N-BOX の表記 |
| そこから考えられること | 丸いチューブは絶対条件ではなさそう → だから Honda は「ド・ディオン式」と呼ぶのだろう |
| 確認できていないこと | **あの横ビームが片輪入力でどれくらいねじれるのか**(だから動きも乗り味も判断できない) |

そして **記事の結論は 3 層目そのもの** です。「名前を知っただけでは足回りを理解したことに
ならない」。つまり、この教材は **分からないことを分からないまま伝える** 必要があります。

gen33 は「6 つ目の図解はそう簡単には釣り合わない。足したくなったら、既存の 5 つで
書いた絵を実際に作って見てから決めろ」と書き残していました。今回もまず
**既存機能だけで 41 枚を作り、資料とスライド画像まで出してから** 判断しています。

## 判断

### 1. 3 層を、章の分け方と「画面の札」の両方で持たせた

まず既存機能だけで作りました。結果はこうです。

* **1 枚の中での対比は、表で足ります。**「確認できたこと / 推測 / 未確認」を 3 行の表に
  すれば読めます(gen31 が「対比は表で足りる」を却下したのは、題が「線」と言っている
  画面に線が無かったからで、ここは題が「三つを分けて話します」なので食い違いません)。
* **「ねじれるなら / ねじれないなら」の二股も、2 行の表で足りました。** 分岐図は要りません。
* **章扉で「ここからは推測です」と宣言するのも効きます。**

**足りなかったのは、1 枚ずつではなく「ずっと効いている」ことでした。** 作った資料の
一覧(contact sheet)を眺めて確かめています —— 25 枚目「丸いチューブは、絶対条件では
なさそうです」は、画面だけ見ると断定に見えます。それが推測だと言っているのは
**4 分前に流れた章扉と、そのときのナレーション** だけです。

> 動画は、頭から最後まで等速で見てもらえるとは限りません。途中から入った人、
> 画面を送った人には、**そのとき画面に出ている文字しか届きません。**

そこで `### 設定` に **`札`** を足しました。短い語を **見出しの行の右端** に出します。
見出しの箱はそのぶん狭くなるので、長い見出しでも重なりません。

```markdown
## 丸いチューブは、絶対条件ではなさそうです

### 設定

- 札: 推測
```

今回は「確認できたこと / 推測 / 未確認 / 問い」の 4 つを使い、**3 枚目で札そのものを
説明する画面** を置きました(札の意味は、札の中には書けません)。

### 2. 札の中身に、描く側が意味を持たせないことにした

**種類ごとに色や形を変えていません。** 変えたほうが目では速いのですが、変えると
「どの語がどの色か」を描く側が決めることになり、**札に書ける言葉があらかじめ用意した
一覧に縛られます。** この道具は「書いたとおりに出す」が前提なので、ここで意味を
決めるのは線を越えます。塗りは 1 色、読むのは文字です。

**読み上げません。** 画面には出ますが、ナレーションには入れません。札の意味を音でも
言うなら `### ナレーション` に書きます(画面の文字を代わりに読まないのと同じ線です)。

**表紙と章扉には置けません**(書いた時点で止めます)。この 2 つには見出しの行が無く、
置き場所が決まらないためです。章扉で同じことを言うなら、見出しの文に書きます ——
今回の「ここからは、確認できた事実からの推測です」がそれです。

### 3. 図解は 5 つのうち 3 つを使い、新しい図解は足していない

| 使った図解 | 枚 | なぜ今回に合うと判断したか |
| --- | --- | --- |
| `枠` | 6 | 「何が一体で上下するか」「見えたものは何か」は、順番ではなく **中身** の話 |
| `流れ` | 6 | 駆動力の伝わり方、片輪入力の伝わり方は **順に進む** 話 |
| `境界` | 1 | ド・ディオンの要点は **デフがバネ上かバネ下か**。線をまたぐのはドライブシャフトが伝える駆動力で、「越える・越えない」そのもの |
| `階段` | 1 | 記事の結論が **「調べてどこまで届いたか」**。形式名 → 構造の定義 → 実物の形 → 分類の理由まで届き、**部材の動きと乗り味には届かなかった** |
| `レーン` | 0 | 担当が 2 つに分かれる話が無い |

**`階段` は gen33 の使い方の写しではありません。** gen33 は「どのモデルがどの Lv まで
届いたか」を複数の到達点で比べました。今回は到達点が 1 つで、**比べているのは
モデルどうしではなく「調べられたところ」と「調べられなかったところ」** です。
記事の最後の一文(形式名を知っただけでは足回りを理解したことにならない)が
そのまま段の並びになるので、合っていると判断しました。

**6 つ目の図解は足していません。** 足したくなったのは 2 か所でしたが、どちらも足りました。

* 「ねじれるなら / ねじれないなら」の **分岐** → 2 行の表で読めます。
* 「確認できたこと / 推測 / 未確認」の **3 つの束** → 3 行の表で読めます。
  (`枠` は束が 1 つ、`境界` は 2 つ、どちらも 3 つは置けません。しかしここは
  **束の中身が 1 行ずつ** なので、表のほうがむしろ読みやすい。)

今回足したのは図解ではなく **画面そのものの属性** なので、「どの図を使うか」で迷う
種類が増えていません。gen33 が心配していた境目には触れていないと判断しました。

### 4. 記事の節順は、ほぼそのまま使った

gen33 の提案 4(「記事から作るときは、節順をそのまま使ってよいかを最初に判断しろ」)に
従って先に見ました。**今回はほぼそのままで良い** と判断しています。この記事は
**調べた順に疑問が増えていく** 形で書かれていて、読者の疑問の出る順と一致しているためです
(普通のド・ディオン → 実物を見たら違う → 昔の Honda → じゃあ何がド・ディオンなのか →
でも横ビームはねじれるのか → 分かったこと・分からなかったこと)。

変えたのは 3 つだけです。

* **「三つを分けて話す」という宣言を、冒頭(3 枚目)へ繰り上げました。** 記事では
  最後まで読んで初めて分かりますが、動画では **最初に言わないと手遅れ** です。
* **記事の末尾にある繰り返し(「本当に知りたかったのは名前ではなかった」が 2 回、
  横ビームの話が 3 回)をまとめました。** 読み物では効きますが、20 分の音声では
  同じ話が戻ってきたように聞こえます。
* **「確認できたこと」「確認できていないこと」を、独立した 2 枚に分けました。**
  記事では地の文に混ざっています。

### 5. 章立てに改行が混ざるのを直した(今回たまたま見つけた)

生成した `_chapters.txt` の 1 行目がこうなっていました。

```
0:00 「ド・ディオン式」なのに、
どう見てもトーションビーム？
```

**章立ては 1 行 = 1 章で、行頭の時刻でしか章を見分けられません。** 時刻の無い行が
混ざると、YouTube はその先を章として読めません。原因は、**表紙の題が収まる幅で
折り返して置かれる** ことで、章立てはその折り返し済みの文字を読んでいました。

**gen33 まで出なかったのは、表紙の題が 1 行に収まっていたからです。** 今回の題が
長かったので出ました。つなぎ直すときに空白を入れるかどうかは、折り返しの前後の
文字で決めます(英語は語の切れ目で折り返すので空白が要り、日本語は文字の切れ目で
折り返すので空白を入れると題に無い空きができます)。

**これは画面を見ても分かりません。**`.txt` を開くか、投稿してはじめて気付きます。
gen33 が「枚数と章数を数えないと気付かない」と書いたのと同じ場所です。

### 判断: 6 つ目の図解(`配置`)を足した

**「図解は 6 つ目を足していない」を覆しました。** gen33 の「足したくなったら、既存の形で
書いた絵を実際に作って見てから決めろ」には、今回も従っています。

| 既存の形 | 13 枚目に使うと |
| --- | --- |
| `枠` | gen34-1 の状態。文の縦並びになる |
| `流れ` `階段` `レーン` | 順番・深さ・担当が無いので、矢印や段が嘘になる |
| `境界` | 上下 2 つにしか分けられない(8 枚目でバネ上・バネ下に使っている) |
| 表 | **実際に作って見ました**(`build/gen34b/try/t.md`)。見出し行が付き、「横ビーム」が 3 回並び、**升目が同じ大きさの文字の箱** になるだけで、つながりも形も読めません |
| 画像(`![](図.png)`) | 描けますが、**絵を外で手作りする** ことになり、「今回だけの手作業」です |

足りなかったのは **「何がどこにあって、何と隣り合っているか」を書く手段** でした。
足したのは機械構造のための機能ではありません。**升目に書いた位置へ、名前の付いた四角を
置くだけ** で、部屋の間取り、機器の並び、画面の区画、盤面でも同じ書き方になります。
ほかの 5 つと役割が重ならない(話の筋ではなく位置を描く)ので、gen33 が心配していた
「どの図を使うかで迷う種類が増える」にも当たらないと判断しました。

決めたことと、その理由です(書き方そのものは README にあります)。

* **書いた位置が、そのまま描かれる位置。** 座標も「〜の右」も書かせません。
  同じ名前を隣り合わせに書けば 1 つのものになります。
* **隣り合うものは、すき間なく接して描く。** 最初にすき間を空ける案も考えましたが、
  すき間があると「並べた札」に見えて、13 枚目の元の問題に戻ります。
  **接していること = つながっていること** とし、つながっていないものの間には
  書いた人が `.` を置きます。
* **升目はすべて同じ大きさ。** 名前の長さで列の幅を変えると、書いた升目と描かれた位置が
  ずれます。位置が図の主題なので、ここは譲りませんでした。そのかわり、最初の試作
  (横 5 升)では **アームが太い板に見えた** ので、横 7 升にしてビームとシャフトを
  またがらせています。これは道具ではなく書き方の側で直しました。
* **升目の数え違いは、書いた時点で止める。** ほかの図解より厳しくしています。
  配置図の数え違いは崩れではなく **「少しずれた、正しく見える図」** になり、
  画像を見ても気付けないためです。空の升目は `.` と書かせ、空のままは誤りにしました。
* **強調(`*`)は、書いた人が付ける。** gen34-1 の「札の中身に、描く側が意味を持たせない」
  と同じ線です。描く側は名前を見ません。**この方針は維持しています。**
* **向きの印(`↑ 車の前方`)を図の上に出す。** 位置を描く図なのに、どちらが前かだけが
  ナレーション頼みになるのを避けました(gen34-1 が札でやったことと同じ理由です)。
* **案内文は、名前と向きだけを言う。**「A の右に B」とは言いません。
  どの関係が大事かを選べるのは書いた人だけです。
