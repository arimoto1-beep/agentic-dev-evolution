ここで、動かしたこと自体とは別の問題が出ました。

* **出力が読めません。** コマンドを(コンソールではなく)パイプ越しに動かすと、日本語が

  環境の確認(`--check`)の結果も、動画の書き出しの結果も、テストの失敗メッセージも、全部そうでした。
* **化けるだけでなく落ちます。** 教材シナリオの題を `🎬教材シナリオのテスト` にして動かすと、
  `UnicodeEncodeError: 'cp932' codec can't encode character '\U0001f3ac'` で終了コード 1。
  シナリオの読み取りは成功しているのに、その題を表示するところで落ちるため、.pptx が作られません。

## 判断

出力の符号化を、コマンドの入口で UTF-8 に固定することを選びました。3 つが重なったためです。

1. **製品の不具合です。** note 記事の題や見出しに絵文字は珍しくありません。
   `cli.py` は取り込んだ記事の題(`result.source.title`)と教材シナリオの題を表示するので、
   README に書いてある使い方のとおりに動かして落ちます。しかも「変換は成功しているのに落ちる」
   ので、原因が中身にあるように見えます。
2. **開発環境の不具合です。** このリポジトリは、失敗したときに何が起きたかを詳しく出すことに
   手をかけています(`proc.CommandError` が実行したコマンドと出力をそのまま載せる、
   `--check` が外部ツールの状態をまとめて出す、テストの失敗理由を日本語で書く)。
   その全部が、読む側に届いていませんでした。**書いた説明が読めないことは、説明が無いことと同じです。**
   この実験の主題は開発環境そのものなので、ここを直す価値は製品としての価値より大きいと考えました。
3. **範囲が小さく、直ったことを機械で確かめられます。** `PYTHONIOENCODING=cp932` を与えれば、
   OS によらず同じ失敗を再現できます。直し方の良し悪しを人の判断に頼らずに済みます。

pytest 自身の出力も同じ扱いにしました。テストの失敗理由が読めないままだと、
**この先の Run が失敗を診断できません。** 効かせる場所は `tests/conftest.py` の
`pytest_configure` です(pytest が出力先を決めたあとでないと効きません)。

### 採らなかった案

1. **`PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` を実行側で指定する。** 使う人の環境に条件が増えます。
   README に「こう起動してください」と書いても、そう起動されない経路(別のツールから呼ばれる、
   スケジュール実行、将来の CI)で同じ失敗が戻ります。**条件を満たさないと落ちる作りのままです。**
2. **`errors="replace"` にするだけ。** 落ちなくはなりますが、読めないままです。2 つの症状のうち
   片方しか直りません。切り替えられない出力先に出会ったときの逃げ道としてだけ残しました。
3. **出力先がコンソールかどうかで分岐する。** Python が既にやっています(コンソールなら
   Windows でも `encoding` は utf-8)。**既に UTF-8 なら触らない** という判定だけで足ります。
   自前で判定を持つと、Python 側の挙動と二重になります。
4. **表示する文字を ASCII の範囲に限る(日本語をやめる、題を表示しない)。** 症状は消えますが、
   説明の質が落ちます。今ある案内文はこのリポジトリの資産です。

## 検証

1. **症状が本当に出るか。** 直す前に再現しました。
   `title: 🎬教材シナリオのテスト` の教材シナリオを渡す -> `UnicodeEncodeError` / 終了コード 1 /
   .pptx が作られない。パイプ越しの日本語はすべて化ける。

2. **直ったか。** 同じ入力で終了コード 0、題が `🎬教材シナリオのテスト` と読める形で出て、
   .pptx ができます。6 つのコマンドすべてで `--help`・`--check`・失敗時の案内が読めることを
   目で確認しました。

3. **テストが落ちるべきときに落ちるか。** 通ることだけを確かめても、何も守っていないテストと
   区別が付きません。

   | 壊したもの | 結果 |
   | --- | --- |
   | `console.use_utf8_output` を何もしない関数にする | 19 件中 12 件が落ちる(6 つのコマンド全部、絵文字の題、失敗時の案内、pytest の出力) |
   | `tests/conftest.py` から呼び出しを消す | 1 件が落ちる(pytest の失敗メッセージが読めなくなる) |

   pytest の出力については、消した状態と入れた状態を実際に並べて、同じ失敗テストの
   メッセージが化ける / 読めるに変わることを確認しました(片方だけ見ても、
   ファイルの置き場所の違いなど別の理由と区別が付かないため)。

4. **既存を壊していないか。** `-m "not slow"` が 706 passed(この Run の前は 687。増えた 19 件は
   今回のもの)。外部ツールを含めると 730 passed(前は 711 件で、うち 1 件が上の取り合いで落ちていました)。**動画も作り直しました**(8 枚 / 3 分 34 秒 /
   字幕 51 件 / 章 8 件)。前と同じものが出ます。

5. **OS に依存しないか。** 再現は `PYTHONIOENCODING=cp932` で作っています。cp932 の変換表は
   Python に同梱されているので、Windows 以外でも同じテストが同じ意味で走ります。
