## 分からないこと

* **gen13 - gen22 が無い理由。** 08-16 と 08-23 の間は 7 日空いています。コミットもタグも
  ありません。Run が失敗したのか、成果を捨てたのか、番号の付け方が変わったのかは判断できません。
* **Run と gen の対応。** `recovery/run005-combined` は「Run005 が gen4 と gen5 を作った」と
  読めるので、Run 1 回 = gen 1 つではありません。gen 番号はコミットに付く番号です。
  この記録も gen 番号に合わせています(タグと一致させるため)。
* **各 Run が何を見送ったか。** 一件も残っていません。これがこの仕組みを作った理由です
  (-> [gen25](gen25.md))。

* 順序は「作れるようにする」-> 「質を上げる」の繰り返しに見えます(gen1-3 と gen5 で
  記事から動画までを通し、gen4・gen6・gen7・gen9・gen10 で読み上げの質を上げ、gen11・gen12 で
  入力を増やし、gen23・gen24 で公開に必要なもの(見た目・サムネイル・字幕・章立て)を足しています)。
  **根拠**: 各コミットの差分の中身。**確認していないこと**: それが意図した順序だったのか、
  結果的にそうなっただけなのか。
* 判断の理由は、残す気が無かったのではなく、**残す場所が README しか無かった** ように見えます。
  README には「候補と、その候補にした理由」「候補に入れなかった声とその理由」(`NOT_CHOSEN`)のように

  README の主題ではない** ため書かれていません。
  **根拠**: README の該当節と `voice_compare.py` の `CANDIDATES` / `NOT_CHOSEN`。
* gen7 だけコミット本文が詳しいのは、原因が分かりにくく、測定値を残さないと再発時に
