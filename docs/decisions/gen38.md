## 判断

### 1. 先に決めた「聞き続けやすさ」

手段の前に、初めて見る人の立場で 6 つ決めました(下の「検証」で、これに照らしています)。

1. 文の終わりが、声の形で終わっている(下がって終わり、次の文で高さが戻る)。
2. 間の長さが、読点 < 文 < 段落 < 画面 の順になっている。
3. 語の途中で止まらない。
4. 問い・発見・結論・断り・並べて言う項目が、声で区別できる。ただし幅は小さく、教材として落ち着いて聞けること。
5. 動きと声が重なる。「こうなります」と言って間を置くなら、その間に動きが見えている。
6. 推測・未確認を、声で事実のように聞かせない。画面(絵・札・断り)は gen37 から変えない。

### 2. いちばん大きい判断: 切れ目を、音程を決める前にエンジンへ伝える

`_read_continuously` で、文や段落の切れ目(と、読点で終わる区切り)に無音の拍を置いてから `/mora_data` を呼び、
音程が決まったあとで間を書いたとおりの長さに置き直します。

* **ひと続きの合成はやめていません。** 1 枚を 1 回で合成するので、Gen7 以前に起きた「区切りごとに書き出しの音程が
  跳ねる」は起きません(1 文ずつ別々の読みは、戻り方が大きすぎる: 上位 10% が +7.4 半音。この方法は +5.6)。
* 道具の側の変更です。題材にも声にもよらず、VOICEVOX で作るすべての動画に効きます。
* **副作用が 1 つあります。** エンジンが切れ目を知ると、切れ目の手前の拍を少し長く言います(人が間の手前でするのと同じ)。
  「間 0.5 秒を足すと音声がちょうど 0.5 秒長くなる」という実機のテストは 0.65 秒になり、テストを書き換えました。

### 3. 間の順序をそろえた

| 切れ目 | gen37 | gen38 |
| --- | --- | --- |
| 読点 | エンジンのまま(0.3 - 0.5 秒) | エンジンの長さの 0.7 倍(0.15 - 0.32 秒) |
| 片仮名の語の「・」 | 0.44 秒 | 0.08 秒(句は分けたまま) |
| 文 | 0.35 秒 | 0.6 秒 |
| 段落 | 0.6 秒 | 0.9 秒 |
| 画面 | 1.0 秒 | 1.0 秒(変えていない) |

* 既定値を変えました(`ReadingStyle`)。Gen7 までに決めた値で、人が聞いて決めた可能性があります。それでも変えたのは、
  当時は読点に 0.39 秒の間が入ることが見えていなかった(合成の中の値で、設定には出てこない)からです。
  **人が聞いて「間延び」と感じたら、ここを戻すのが最初の手です**(`--sentence-pause` `--line-pause`)。
* 動画は 44 秒長くなりました(18:19 → 19:04)。読点で縮めたぶんより、文と段落で延ばしたぶんが大きい。
* 文の途中の合図(`まず、〔1〕教科書に…`)で読点の間が消えていたのも直しました(gen36 が「文の途中の合図で抑揚が
  変わっていないか」を気にしていた所。間が消えていた)。

### 4. 「ド・ディオン」: 判断が途中で変わった

**最初は「・」を消して 1 語として読ませました**(読みの段で `ド・ディオン → ドディオン`)。理屈は「名前の途中で止まるのはおかしい」。
完成した音声を自然さの推定器(UTMOS。下の検証)にかけると、41 場面中 12 場面で gen37 より下がりました。
変更を 1 つずつ外して合成し直す比較(`analysis/ablation.py`)で、下がった場面の多くは「・」を戻すと推定が戻りました。
**1 語にすると、アクセントが変わる** のが原因と考えました(エンジンは「ド」と「ディオン式」を別々の句として読むのが前提で、
1 語にすると違う高さの並びになる)。そこで、句は分けたまま、止まる長さだけを 0.08 秒に縮める形に改めました。
4 通り(0.45 秒 / 0.08 秒 / 止まらない / 1 語)を推定器にかけると、平均 3.46 / 3.43 / 3.40 / 3.31。
音声認識は、0.08 秒の版を 38 回とも「ド・ディオン」と書き起こしました(gen37 は 12 回「ド、ディオン」)。

**どれが正しい言い方かは、私には決められません。** 4 通りを `build/gen38/listen/name/` に置き、人に聞いてもらうことにしました。

### 5. 話す調子は、役割で書く

gen37 の `〔声 ゆっくり〕` `〔声 速め〕` は話し方の指定でした。書く人が文ごとに加減を考えることになり、同じ役割の文が
場所によって違う読み方になります。**役割(問い・発見・結論・補足・列挙)で書けるようにし、役割から話し方を決めるのは道具の側** にしました。
次の題材でも同じ意味で使えます。話し方の合図は、そのまま残しています(gen37 の原稿が読めるように)。

* 役割ごとの違いは「拍の長さ・高さの動き・声の高さ」の 3 つだけ。どれも小さい(声の高さは -1 - +1.5 半音)。
  聞いて確かめていない幅には広げない、という gen37 の判断を維持しました(テストで幅を押さえています)。
* 「比較」は役割にしませんでした。比較は 2 文の関係で、1 文の話し方ではないからです。かわりに **強調**(`〔強 ことば〕`)を足し、
  対比の核心(ねじれます / ねじれません)を強調します。強調した語は少し高く・少し長く、同じ区切りの後ろは抑揚を少し小さくします
  (日本語で焦点のあとの抑揚が小さくなる形をなぞったもの)。
* **推測・未確認を事実のように聞かせないために**: 推測の章の文には「結論」も強調も付けない。強調するのは
  「推測」「確認できていません」「分かりません」の語。下読み(`note2slides-reading`)の最後に、調子を変えた文を
  役割ごとに並べるようにしました。これで「個人的には、ここがいちばん気になるところです」が「発見」の調子のまま続いているのを、
  音を作る前に見つけて直しています。
* この動画では、問い 8・発見 9・結論 6・補足 5・列挙 20 文、強調 27 語。全 259 文のうち調子を変えたのは 48 文です。
  **残りの 8 割は「ふつう」のままです。** 単調さに効くのは、役割より先に、全部の文に効く 2 と 3 だと判断したためです。

### 6. 動きと声を合わせた

動きの合図を、動きを言う語へ移しました(`タイヤが〔4〕上下すると、こうなります。` `段差に乗って、〔2〕持ち上がります。`)。
最初は「こうなります」に置き、1 回目の動画で測り直すと、9 枚目は次の段に動きを切られ、ほかの 3 か所は動きのあとに
1 - 1.8 秒止まった絵が残っていました。合図の位置と `〔間〕` の長さを、動きの長さ(1.6 - 3.0 秒)に合わせて直しています。
README に「動きを見せる段は、動きを言う語に合図を書く」と足しました。

### 7. 聞けないことに、どう向き合ったか

**今回の中心です。** 音を聞く手段は、この環境にありません。聞く代わりにはならないが、聞かずに作ったときの崩れを
見つける手段を 4 つ用意し、**使う前に、それが何を見分けるかを確かめました**。

| 手段 | 使う前に確かめたこと |
| --- | --- |
| 拍ごとの高さ(合成の前の値) | 音になる値そのもの。測った形は、完成した音声の波形でも同じ向きに出た |
| 声の形(波形から。`prosody.py`) | gen37 の崩れ(上がって終わる・低く始まる)を数字で見分けられた |
| 自然さの推定(UTMOS) | 英語中心の学習。日本語の 8 場面を、明らかに崩した読み方(抑揚を平らに・でたらめな揺れ・1.45 倍速)と比べ、崩したほうを 7 - 8 / 8 場面で低く出した。過去に人が耳で退けた方法(1 文ずつ合成)も低く出した。音量や先頭の無音を変えても ±0.02 しか動かない。**差は小さく(0.1 - 0.6)、1 場面ごとの上下は決め手にしない** |
| 音声認識(Whisper large-v3) | 何と聞き取られるか。読み違いと、語の途中の切れ目(「ド、ディオン」)は分かる。句点は粗い目安 |

推定器は、**私の判断の誤り(「・」を消した)を 1 つ見つけました。** 聞けないことを、数字で埋めたつもりになると危ない、
という逆の例でもあります。私は「名前の途中で止まるのはおかしい」という理屈で 1 語にしましたが、それは聞いて確かめた判断ではなかった。

### 8. 現在の環境に引っ張られていないか

* **変えた: 「1 枚を切れ目の無い 1 文として音程を決める」。** Gen7 以前からの前提でした。区切りごとの合成をやめた理由は正しく、
  その方法のほうに副作用がありました。
* **変えなかった: 声(VOICEVOX Nemo 男声3)とエンジン。** 別のエンジン(AivisSpeech など、文脈から抑揚を決めるもの)を使えば、
  もっと自然になる可能性はあります。採らなかったのは、(a) 声は人が聴き比べて決めたもので、聞かずに変えるのは人の判断を覆すこと、
  (b) 見つけた原因は、エンジンの力ではなく **エンジンへの渡し方** にあり、1 文ずつ読ませたときのエンジン自身の形はまともだったこと。
  渡し方を直す前に声を替えると、何が効いたのか分からなくなります。
* **引っ張られたと認めるところ: 間の長さの既定と、役割の幅。** 本来は聞いて決める値を、文献的な順序(読点 < 文 < 段落)と、
  小さい幅で決めています。

## 見送り

* **声・エンジンを替えること。** 上の 8。見直す条件: 人がこの版を聞いて「まだ機械的」と言ったとき。そのときは、同じ原稿の
  数文を、いまの声と別のエンジンで作って、人に聴き比べてもらうのが先です(`note2slides-voices` がその道具)。
* **BGM・効果音。** gen37 と同じ理由(鳴らした結果を確かめられない・素材の権利)。今回は間を長くしたので、無音がより目立つ
  可能性があります。人への質問として残します。
* **音量の上限の調整。** 警告は残っていますが、抑えているのは声の 0.1% の時間(5dB 以上)。下げる量より、警告が時間を言わないこと
  のほうが問題かもしれません(「最大 7dB」は大きく聞こえる)。直していません。
* **段落の頭で声を少し高くする(段落の抑揚)。** 文の頭で高さが戻るようになったので、段落の区別は間の長さ(0.9 秒)に任せました。
  入れると「変化を増やすこと自体」になりかねない。聞いた人が「段落の変わり目が分からない」と言ったら試す価値があります。
* **評価用の環境(torch・Whisper・UTMOS)を本体の依存に入れること。** 3.5GB あり、動画を作るのに要りません。`tools/voice_check/` に
  置き、別の環境の作り方を README に書きました。
* **字幕の時刻を、合成の前に分かる正確な時刻にすること**(gen36 から)。字幕は拍の数の見積もりのままです。

   読点の間を戻したので減った)。

   上の 2 の副作用で実機のテスト 1 件)。**これは実装の確認で、声の出来の根拠にはしていない。**

### 良くなっていないと思うところ・確かめていないこと

* **声は 1 つの声のままです。** 18 分以上、同じ人格の無い声が続くことは変わっていません。
* 役割の調子を変えたのは 2 割の文です。8 割の文は、文の形が戻っただけで、話し方は同じです。
* 推定器が下がった場面が 7 つ残っています(3 枚目 -0.42、6 枚目 -0.18、38 枚目 -0.12 ほか)。3 枚目は「ド・ディオン」、
  6 枚目は「まず、」のあとに読点の間を戻した所。どちらが良いかは聞かないと分かりません。
* 無音は、まったくの無音のままです(背景の音が無い)。間を長くしたぶん、途切れに聞こえる可能性があります。
* 長くなった 44 秒が、落ち着きに聞こえるか、間延びに聞こえるか。
* 文の途中に置いた 3 つの動きの合図の時刻は、音声では確かめていません(計算した時刻のまま)。
