# 改善の記録

この開発環境は Run(AI の 1 セッション)をまたいで改善を続けています。
コード・README・テスト・Git 履歴を読めば「今どうなっているか」はかなり復元できますが、
次のことは残りません。

* なぜその改善を優先したのか
* 何を見送り、なぜ見送ったのか
* 次に何へ取り組む価値が高いと考えたのか

ここには、それだけを残します。

## 新しい Run が最初にすること

1. [一覧](#一覧)の下から数件を読む(直近の Run が何を考えていたか)
2. 書かれていることを **提案として** 扱う
3. 現在のリポジトリと目的に照らして、維持・変更・却下を自分で決める
4. 決めた結果と理由を、自分の記録の「過去の判断の再評価」に書く

過去の記録は指示ではありません。**そのまま実行するためではなく、評価し直すために** 置いてあります。
当時の判断は当時の状態に対して正しかっただけで、前提が変わっていれば今は正しくありません。
そのため各記録は「この Run が見た状態」から始めます。そこが今と違っていれば、判断ごと疑って構いません。

却下してよいのは提案だけではありません。**この記録の付け方そのもの**(見出し・粒度・置き場所)も
評価の対象です。合わないと判断したら変えてください。ただし変えた理由は記録してください。

## 書き方

Run の終わりに `docs/decisions/genNN.md` を追加し、[一覧](#一覧)に 1 行足します。
`NN` は直近の記録の次の番号です(Git のタグと同じ番号を使います)。

見出しは次の 6 つを使います(`tests/test_decision_log.py` が形を確認します)。

| 見出し | 書くこと |
| --- | --- |
| `## この Run が見た状態` | 判断の前提にした事実。あとから「前提が変わったか」を確かめるために書く |
| `## 判断` | 何を優先したか、なぜそれを選んだか。採らなかった案があればそれも |
| `## 見送り` | 見送ったこと、その理由、どうなったら見直すか |
| `## 検証` | どう確かめたか。次の Run が同じ手順を踏めるように書く |
| `## 過去の判断の再評価` | 読んだ範囲と、維持・変更・却下したもの。無ければ「なし」と書く |
| `## 次の Run への提案` | 価値が高いと考えること。理由も書く(理由が無いと評価できない) |

**コードと README と Git 履歴を読めば分かることは書きません。** 実装の内容は差分に、
使い方は README にあります。ここに残すのは、そこから復元できない判断だけです。

過去の記録に対して判断が変わったときは、その記録を書き換えず、自分の記録に書きます
(当時どう考えていたかが消えると、比べられなくなります)。あわせて一覧の「その後」を更新し、
どの Run で変わったかを追えるようにします。
