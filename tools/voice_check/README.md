# 声を聞けないときの確認(voice_check)

この開発環境で動く AI は、作った音声を **聞けません**。ここにあるのは、聞く代わりにはならないが、
**聞かずに作ったときに起きやすい崩れを、聞く前に見つける** ための道具です(Gen38 で作りました)。

**どれも「聞いて確認した」ことにはなりません。** 数字が良くても、自然に聞こえるとは限りません。
最後は人が聞いて決めます。記録や README には「測った」「推定した」と書き、「聞いた」と書かないでください。

| 道具 | 何が分かるか | 何が分からないか | 必要なもの |
| --- | --- | --- | --- |
| `prosody.py` | 文末が下がっているか・上がって終わっていないか、間のあとで高さが戻るか、間の長さが読点・文・段落で分かれているか、ひと続きに話す長さ | 声の質、抑揚が「自然な形」か、言い方が内容に合っているか | `.venv`(追加なし) |
| `av_check.py` | 画面の動き(段へ移る連番)が、声のどこに重なっているか。動きのあとの無音の長さ。声に合わせる動き(`fit` / `loop`)は、次の合図までの長さで測る | 動きと声が合って **見える** か | `.venv`(追加なし) |
| `utmos.py` | 学習済みの自然さの推定(1 - 5)。明らかに崩れた読み方を低く出す | 細かい良し悪し。日本語の抑揚への感度は弱い(下記) | 評価用の環境 |
| `asr.py` | 音声認識で何と聞き取られるか(読み違い、語の途中の切れ目)。文字の誤り率 | 聞き取れることと、聞きやすいことは別 | 評価用の環境 |

## 使い方

```bash
# 声の形(前の版と並べる)
.venv/Scripts/python.exe tools/voice_check/prosody.py build/gen38/work/audio build/gen37/work/audio

# 動きと声
.venv/Scripts/python.exe tools/voice_check/av_check.py build/gen38/dodeon/dodeon_scenario.md build/gen38/work/audio

# 自然さの推定と音声認識(評価用の環境で)
<評価用の環境>/Scripts/python.exe tools/voice_check/utmos.py build/gen37/work/audio build/gen38/work/audio
<評価用の環境>/Scripts/python.exe tools/voice_check/asr.py build/gen38/work/audio
```

### 評価用の環境

UTMOS と Whisper は torch を使うので、本体の `.venv` とは分けます(本体の依存には入れていません。
動画を作るのに要らない 3GB を、全員に入れさせないため)。置き場所は `build/` の下にします(コミットしない)。

```bash
python -m venv build/evalenv
build/evalenv/Scripts/python.exe -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128
build/evalenv/Scripts/python.exe -m pip install faster-whisper soundfile numpy
# モデルの置き場所(C ドライブを使わないため。初回に約 3.5GB を取ってくる)
export HF_HOME=$PWD/build/hf TORCH_HOME=$PWD/build/torchhub
```

GPU が無ければ CPU で動きます(遅い)。Gen38 では RTX 2070 SUPER で、18 分の音声を UTMOS 1 分・Whisper 数分でした。
faster-whisper にファイル名を渡すと、PyAV の版によって読めないので、`asr.py` は配列にしてから渡しています。

## 確かめた範囲(Gen38)

**UTMOS は英語の音声で主に学習したモデルです。日本語の抑揚の良し悪しを見分けるかは、使う前に確かめました。**
同じ 8 場面を、良し悪しが分かっている読み方で合成して採点しています(`build/gen38/analysis/variants.py`)。

| 読み方 | 平均 | いまの方法より低かった場面 |
| --- | --- | --- |
| いまの方法(Gen38) | 3.48 | - |
| Gen37 の方法 | 3.39 | 7 / 8 |
| 文を 1 つずつ別々に合成(Gen7 以前の方法。人が聞いて退けた) | 3.35 | 7 / 8 |
| 抑揚を平らにした(明らかに悪い) | 3.25 | 7 / 8 |
| 高さをでたらめに揺らした(明らかに悪い) | 3.27 | 8 / 8 |
| 1.45 倍速(悪い) | 2.83 | 8 / 8 |

* 明らかに崩した読み方は低く出し、過去に人が耳で下した判断(続けて合成するほうが良い)とも合った。
* ただし差は小さい(0.1 - 0.6)。**1 場面ごとの上下は決め手にしない。** 多くの場面での平均と、上がった場面の数を見る。
* 先頭に無音を足す・音量を 1dB 下げる、では ±0.02 しか動かない。0.2 以上の差は、内容の違いに反応している。
* Gen38 では、この道具が **自分の判断の誤りを 1 つ見つけた**:「ド・ディオン」の「・」を消して 1 語として読ませたら、
  その語を含む場面の推定が軒並み下がった(アクセントが変わる)。止まる長さだけを縮める形に改めた。
  **推定が下がった場面は、捨てずに原因を探す価値がある。**

Whisper の句点は、Gen37 の読み方(文末が下がらない)では 55 文に 17 個、Gen38 では 43 個でした。
「全部打つか、まったく打たないか」に振れやすいので、粗い目安にとどめます。Gen37 の音声を「ド、ディオン式」と
書き起こしたのは、語の途中で止まっていることの、分かりやすい証拠でした。

## 人が聞かないと分からないこと

* 抑揚が自然か、機械的に聞こえないか。役割(問い・結論など)の読み方が、内容に合って聞こえるか。
* 間が「間」に聞こえるか、「途切れ」に聞こえるか。
* 強調が強すぎないか、わざとらしくないか。
* 18 分聞き続けて疲れないか。
