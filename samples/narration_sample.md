# 情報セキュリティの基本

## この講座で学ぶこと

情報セキュリティは、専門の担当者だけが気にすればよいものではありません。業務で扱う情報の多くは、日々の作業の中で受け取り、加工し、誰かに渡しています。その一つ一つの場面に、情報が外へ出てしまう可能性があります。

この講座では、日常の業務で実際に判断が必要になる場面を取り上げ、何をどう判断すればよいのかを整理します。専門の用語はできるだけ使わず、明日からの作業でそのまま使える形にしています。

## 守る対象を決める

すべての情報を同じ強さで守ろうとすると、手続きが増えすぎて業務が止まります。まず、守る対象と、その重要度を決めます。

1. 個人情報を含むもの
2. 取引先から預かったもの
3. 社外に出していない検討中の資料
4. すでに公開している情報

上から順に、扱いを慎重にします。すでに公開している情報まで同じ手続きで扱う必要はありません。

### 重要度の見分け方

判断に迷ったときは、その情報が社外に出たときに誰が困るかを考えます。

- 特定の個人が困るなら、個人情報として扱う
- 取引先が困るなら、契約上の秘密として扱う
- 自社の交渉が不利になるなら、社内限りとして扱う
  - 判断が付かない場合は、上長に確認する
  - 確認できるまでの間は、慎重な側で扱う

> 迷ったときに慎重な側を選べるかどうかが、事故になるかどうかの分かれ目になります。

## 事故が起きる場面

実際に報告されている事故の多くは、高度な攻撃によるものではなく、日常の作業の中で起きています。次の表は、社内で報告された事故を場面ごとにまとめたものです。

| 場面 | よくある原因 | 防ぎ方 |
| --- | --- | --- |
| メール送信 | 宛先の選び間違い | 送信前に宛先を声に出して確認する |
| ファイル共有 | 共有範囲の設定漏れ | 共有先を個人単位で指定する |
| 端末の持ち出し | 置き忘れ | 持ち出す前に必要かどうかを確かめる |
| 異動と退職 | 権限の消し忘れ | 予定を人事とあらかじめ共有する |

どれも、作業そのものは数秒で終わるものです。手順を増やすよりも、確認する場面をあらかじめ決めておくほうが長続きします。

## パスワードとアカウント

パスワードは、長さが最もよく効きます。記号や数字を混ぜることよりも、まず長くすることを優先してください。

- 12 文字以上にする
- サービスごとに違うものにする
- 覚えきれなくなったら、パスワード管理ソフトを使う

多要素認証を有効にできるサービスでは、必ず有効にします。パスワードが外に出てしまった場合でも、そこで止められます。

自分のアカウントがいつどこから使われたかは、次のコマンドで確認できます。

```bash
account-audit --since 2026-04-01 --format csv
```

身に覚えのない記録が見つかった場合は、その場でパスワードを変え、情報システム部に連絡してください。

## 社外とのやり取り

社外へ情報を出す場面は、渡し方によって注意するところが変わります。同じ資料でも、メールに添付する場合と、共有リンクを送る場合では、後から取り消せる範囲が違います。

| 渡し方 | 気を付けること | 渡したあとにできること |
| --- | --- | --- |
| メールの添付 | 宛先と添付ファイルの取り違え | 取り消せない |
| 共有リンク | 期限と閲覧範囲の設定 | 期限切れと権限の取り消し |
| 外部媒体 | 持ち運びの間の紛失 | 回収するまで分からない |

取り消せる渡し方を選んでおくと、間違いに気付いたときに手が打てます。急ぎの用件ほど、後から直せる方法を選んでください。

### 宛先を確かめる

宛先の確認は、送信ボタンを押す前の数秒で終わります。次の順で見ると、取り違えに気付きやすくなります。

1. 宛先の会社名を見る
2. 宛先の氏名を見る
3. 添付ファイルの名前を開いて見る
4. 本文に書いた相手の名前と、宛先が同じかを見る

似た名前の相手が候補に並ぶ場合は、入力補完に任せず、一度消してから入力し直します。

> 送信の取り消しは、相手の環境によっては効きません。押す前に確かめることが唯一の対策です。

## 在宅勤務と持ち出し

自宅や移動中の作業では、画面と音声が周囲に見聞きされる可能性があります。社外の場所では、画面の向きと通話の音量を先に決めてから作業を始めてください。

- 背後に人が通る場所では、画面を壁側に向ける
- 会議の音声はイヤホンで聞く
- 席を離れるときは、短い時間でも画面を閉じる

端末を持ち出す前に、その日に使う情報だけが入っているかを確かめます。使わない資料を入れたまま持ち歩くと、紛失したときの影響が広がります。

自分の端末に何が保存されているかは、次のコマンドで一覧にできます。

```bash
device-inventory --scope documents --format table
```

覚えのないファイルが残っていた場合は、消す前に情報システム部へ連絡してください。消してしまうと、いつ入ったのかが分からなくなります。

## 委託先とのやり取り

作業を外部へ委託する場合、渡した情報の扱いは委託先の運用に左右されます。契約を結んでいても、実際にどう扱われるかは、渡す前に決めておかないと確かめられません。

1. 渡す情報を、作業に必要な範囲まで減らす
2. 個人情報が含まれる場合は、置き換えられないかを検討する
3. 作業が終わったあとの返却と削除の方法を決める
4. 決めた内容を、担当者どうしで同じ文面で確認する

作業が終わったあとに削除を依頼しても、控えが残っていることがあります。始める前に決めておけば、終わったときに確かめるだけで済みます。

## よくある誤解

説明のときによく出てくる質問を、四つ挙げます。どれも、正しそうに見えて事故につながる考え方です。

| 誤解 | 実際 |
| --- | --- |
| 社内なら誰に送っても問題ない | 権限のない社員に渡ると、そこから外へ出ることがある |
| パスワード付きの圧縮なら安全 | 同じ経路で送ると、一緒に漏れる |
| 少しの情報なら影響は小さい | 他の情報と組み合わさると個人が特定される |
| 気付かれていないなら大丈夫 | 気付かれていないだけで、影響は進んでいる |

判断に迷ったときは、その場で決めずに確認してください。確認にかかる時間は、事故の対応にかかる時間よりはるかに短くて済みます。

## 事故が起きたときは

事故が起きたとき、最も避けたいのは報告が遅れることです。報告が遅れるほど影響は広がり、選べる対応も減ります。叱られることを心配して数時間黙っていた結果、取り返しがつかなくなった例が実際にあります。

1. 作業をその場で止める
2. 上長と情報システム部に連絡する
3. 端末とファイルはそのままにしておく
4. 気付いた時刻と操作を書き留める

自分で解決しようとして操作を続けると、原因を調べるための記録が消えてしまうことがあります。まず連絡してください。

## まとめ

情報セキュリティは、特別な作業ではなく、日々の判断の積み重ねです。

守る対象を決めること、迷ったときは慎重な側を選ぶこと、起きたときはすぐ報告すること。この三つを覚えて帰ってください。
